# 마무리 — 제출 전 약 25분

공통 문서 정리와 커밋은 메인만 한다. 보조 역할에서 마무리를 요청받으면 자기 역할 보고서의 결론·미해결 사항을 정리해 메인에 전달하고, 아래의 쓰기 작업은 수행하지 않는다.

1. **동작**: 처음 상태에서 실행 방법대로 다시 돌린다. 테스트 전체를 돌린다.
2. **제출 문서**: `SUBMISSION.md`(또는 과제가 정한 파일명)를 채운다. 재료는 `PLAN.md`·`NOTES.md`·`STATE.md` 진행 기록·`git log`.
3. **문서와 코드 대조**: 제출 문서의 문장마다 근거(`파일:줄`·커밋·명령 출력)가 실제로 있는지 하나씩 확인한다.
   근거가 없거나 코드와 다른 문장은 고치거나 지운다. 하지 않은 것을 했다고 쓰지 않는다.
4. **약점 세 개**: 사람이 직접 적는다. 형식은 「약점 지점 · 파급 · 다음 검증」.
5. **민감 정보**: `git grep -nE` 로 키·토큰·개인정보 값이 커밋에 없는지 본다.
6. **정리**: `git status` 가 깨끗한지, 과제가 요구한 파일이 정한 경로에 있는지 본다. 마지막 커밋.

## 넘기기 전 점검 (사람)
- `.harness/GOAL.md` 3절 순서로 점검한다. STATE.md의 중간 이해 점검에서 미해결인 부분과 이후 변경된 부분을 우선한다.
- 처음부터 전체 구조를 다시 설명하는 대신, 핵심 파일 2~3개를 사람이 직접 읽고 이해한 내용과 현재 코드가 일치하는지 확인한다.
- 설명하지 않은 중요한 부분이 발견되면 `checkpoint`를 적용한다. 이해하지 못한 부분은 이해 확인으로 기록하지 않는다.
- 사용자가 설명 연습이나 모의 문답을 요청하면 `explain-back`을 적용한다. 중간 점검에서 이미 이해한 전체 내용을 반복하거나 별도 연습을 자동으로 강제하지 않는다. AI 사용이 금지된 단계에서는 실행하지 않는다.
- NOTES.md의 「되돌린 시도」와 현재 코드를 대조해 복구가 끝났는지, 남은 실패가 SUBMISSION.md의 한계와 일치하는지 확인한다.
