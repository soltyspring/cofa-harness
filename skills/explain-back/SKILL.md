# 설명 되돌리기

원본 cofa-harness의 explain-back을 세 역할과 중간 이해 점검에 맞게 조정했다.
목적은 사람이 자신의 산출물을 설명하고 이해의 빈틈을 찾는 것이다. 실제 평가 질문이나 정답을 예측하는 도구가 아니다. AI 사용이 금지된 단계에서는 실행하지 않는다.

## 기본 원칙
- 요청을 받았을 때만 실행한다. 평소 checkpoint의 「쉬운 설명 → 짧은 이해 확인」은 그대로 유지한다. 이 모드는 「사람이 먼저 설명 → 코드와 대조」다.
- 대상 함수·호출부·관련 요구와 검사 근거부터 읽는다. 대상을 지정하지 않으면 최근 변경에서 핵심 함수 하나를 고른다. 아직 구현이 없으면 그 사실을 밝히고 목표나 입력→출력 예시 하나를 대상으로 한다.
- 대상 파일:줄과 검토 버전을 밝힌다. 미커밋 변경도 구분하며 연습 중 관련 코드가 바뀌면 달라진 부분을 다시 확인한다. 예시는 민감값을 가리거나 작은 가상 입력을 사용한다.
- 코드·설정·테스트·제출 문서를 고치거나 검사를 새로 실행하지 않는다. `.harness/roles.md`의 쓰기 범위를 지킨다. 이해 도우미는 자기 보고서, 메인은 STATE.md에 실제 확인 상태를 기록한다. 역할을 몰래 바꾸거나 다른 세션을 자동 실행하지 않는다.

## 기능 하나 설명하기 — 약 3분
사용 예: `$explain-back <함수나 기능>` 또는 「설명 연습」.

1. 대상 코드 위치와 입력 예 하나를 제시한다. 아래 중 필요한 질문 **하나만** 내고 사용자 답을 기다린다. 모범 답안을 먼저 보여주지 않는다.
   - 이 입력은 어떤 순서로 처리되고 무엇이 나오나? 중간 상태는 어디에 남나?
   - 왜 이 방식이나 자료구조를 골랐나? 불리한 점이나 검토한 다른 방법은?
   - 어떤 입력에서 결과가 틀리거나 실패하나? 현재는 어떻게 처리하나?
   - 무엇을 실제로 검사했으며 기대값은 어떤 근거로 정했나?
2. 실제 답을 코드·기록과 대조해 「맞는 부분 / 다른 부분 / 빠진 부분」을 파일:줄과 함께 짧게 알려준다. 실행하지 않은 동작은 코드상 예상과 미검증으로 구분한다.
3. 사용자가 모르겠다고 하면 먼저 읽을 코드 한 구간과 힌트 하나를 준다. 사용자가 설명을 원하면 작은 예제로 가르치는 checkpoint 방식으로 돌아간 뒤 다시 설명할 기회를 준다. 설명만 들은 상태를 이해 확인으로 올리지 않는다.
4. 이해가 확인되면 끝내거나 다음 질문 하나로 넘어간다. 생략하거나 중단하면 남은 부분을 미확인으로 남긴다. 긴 문답을 끝까지 강제하지 않는다.
5. 원하면 사용자가 NOTES.md의 「내 설명」에 직접 한 줄을 남긴다. AI가 그 표를 대신 채우지 않는다. 역할별 이해 상태·미해결 질문 기록은 실제 사용자 답만 근거로 작성한다.

## 선택 모의 문답 — 남은 시간 안에서
사용 예: `$explain-back 모의` 또는 「모의 문답」. 기능 동결 후 사용자가 요청한 경우에만 진행한다. 기본은 약 20분 이내이며 제출·검증 시간을 침범하지 않는다.

- 실제 제출물과 기록을 근거로 구조·동작, 선택 이유, 예외·변경, 검증 근거, AI 제안에 대한 판단을 다루는 질문을 최대 6개 고른다. 고정 기출·실제 평가 기준이라고 말하지 않는다.
- 그중 하나는 코드나 문서와 다른 전제를 가진 질문으로 만들 수 있다. 검토에서는 전제가 틀렸다는 점도 분명히 밝힌다.
- 한 번에 하나만 질문하고 답을 받는다. 이 모드에서는 중간 교정 없이 다음으로 넘어간다. 「모르겠다」도 답으로 받아들이며 내용을 대신 만들어 주지 않는다.
- 마지막에 `질문 / 실제 답과 근거의 일치·부분 일치·확인 불가 / 다른 부분 / 다시 읽을 코드`를 짧게 정리한다. 이 판정은 이해 연습용이며 실제 점수 예측이 아니다.
- 문서의 과장이나 코드와의 불일치는 메인에게 수정 제안으로 전달한다. 이 스킬이 문서를 대신 고치지 않는다. 숫자는 기존 실행 근거가 있는 것만 제시한다.
