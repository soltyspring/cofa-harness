# 중간 이해 점검

목적: 사람이 작업 중에 구조와 검증 결과를 이해한다. 마지막에 처음부터 배우게 하지 않는다.

기본은 쉬운 설명 뒤 짧은 이해 확인이다. 사용자가 「설명 연습」·「설명 되돌리기」·「모의 문답」을 요청한 경우에만 `.agents/skills/explain-back/SKILL.md`로 사람이 먼저 설명하는 모드를 진행한다. 매 checkpoint를 긴 문답으로 바꾸지 않는다.

## 시점과 분량
- 첫 입력→출력 실행본, 주요 기능 완료, 중요한 설계 변경 때 적용한다. 마지막 점검 후 약 25분이 지났으면 다음 자연스러운 작업 경계에서 적용한다.
- 같은 시점의 점검은 한 번으로 합친다. 오탈자·작은 스타일 수정마다 반복하지 않는다. 장시간 명령은 상태를 알리고 완료 후 결과로 점검한다.
- 기본은 사람이 1~2분에 읽을 수 있는 다섯 항목이다. 전체 프로젝트 설명 대신 직전 점검 이후 달라진 부분을 설명한다.

## 설명할 것
1. **이번 선택**: PLAN.md S 번호, 바꾼 기능, 선택 이유와 불리한 점. 실제 검토한 대안이 없으면 없다고 한다.
2. **동작과 상태**: `파일:함수 → 파일:함수`로 입력부터 출력까지 짚고, DB·파일·메모리 중 무엇에 누가 읽고 쓰는지 설명한다. 핵심 코드 한 구간을 링크한다.
3. **확인한 결과**: 실행 명령, 대상 코드 버전과 입력, 기대값의 근거, 실제값, 통과·실패·미검증을 보여 준다. 기존 검사 결과를 재사용해도 되며 설명용으로 중복 실행하지 않는다. 테스트 개수만으로 정확하다고 결론 내리지 않는다.
4. **경계와 한계**: 이번 기능에 중요한 예외 하나의 현재 동작을 설명한다. 실행하지 않은 상황은 예상과 미검증으로 구분한다. 재실행·설정 변경·데이터 교체는 관련된 기능에서만 다룬다.
5. **사람이 확인할 한 가지**: 핵심 코드나 출력 하나를 가리키고 자신의 말로 동작 또는 판정 이유를 설명해 보도록 짧게 요청한다. 모범 답안을 먼저 써 주지 않는다. 답이 오면 맞는 부분과 빠진 부분만 근거로 교정한다.

## 기록과 계속하기
- 역할과 쓰기 권한은 `.harness/roles.md`를 따른다. 이해 도우미는 설명과 실제 사용자 답을 자기 보고서에 기록하고, 메인이 읽어 STATE.md에 반영한다. 검증 보조는 공통 기록을 수정하지 않는다.
- 이해 도우미가 활동 중임을 사용자가 알렸으면 메인은 변경·검사 근거와 짧은 요약을 제공하고 도우미가 상세 설명을 맡는다. 도우미가 없으면 메인이 직접 설명한다. 파일 기록만으로 다른 세션이 자동 실행된다고 가정하지 않는다.
- 메인 세션만 STATE.md의 「이해 점검」을 갱신한다. 관련 결정은 NOTES.md의 기존 기록에 이유·대가·증거를 보완한다. 별도 장문 문서는 만들지 않는다.
- 상태는 `미확인 / 설명 제공 / 본인 설명 확인 / 보완 필요`다. 읽었다고 추정하거나 AI가 쓴 문장으로 본인의 이해를 대신 인증하지 않는다.
- 사용자의 답을 기다리느라 매번 전체 작업을 멈추지 않는다. 기존 합의 안에서 독립적으로 진행할 일은 계속한다. 답이 없으면 미확인 사항을 남기고 다음 점검에서 우선 다룬다. 범위·요구의 새 결정이 필요한 작업은 답을 받은 뒤 진행한다.
- 같은 내용을 재설명할 때는 미해결 부분과 변경된 부분만 다룬다. 다음 세션도 STATE.md의 미해결 사항을 이어받는다.
- 실패를 성공으로 바꾸어 기록하거나, AI 제안 기각·실험·사람 답변을 지어내지 않는다.
