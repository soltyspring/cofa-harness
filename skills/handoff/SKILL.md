# 인계 — 세션을 끊고 이어 가기

대화가 길어지면 압축을 거듭하지 말고 인계한다. 시점을 미리 정한다.

## 언제
- 단계가 바뀔 때(합의 → 구현, 구현 → 마무리)
- 시작 후 약 90분
- 같은 오류를 두 번 고쳤는데 또 날 때

## 어떻게
1. `STATE.md` 의 「현재」를 덮어쓴다: 단계 · 된 것 · 남은 것(우선순위) · 알려진 문제 · 마지막 검사 · 다음 할 일. 「다음 할 일」은 새 세션이 바로 실행할 수 있게 파일과 명령까지 쓴다.
   「이해 점검」의 마지막 설명 대상·근거 버전·사람의 확인 상태·미해결 질문도 이어받게 한다. 설명하지 못한 부분을 완료로 바꾸지 않는다.
   검증·이해 도우미의 보고서가 있으면 대상 버전과 현재 코드가 맞는지 확인한 뒤 중요한 미해결 사항을 반영한다. 보조가 이 절차를 사용할 때는 공통 문서 대신 자기 역할 보고서만 갱신하고 커밋하지 않는다.
2. 요구가 바뀌었으면 `PLAN.md` 도 고친다.
   NOTES.md의 「되돌린 시도」에 실제 실패·복구·다음 접근이 기록되어 있는지 확인하고, 반복하면 안 되는 조건과 미해결 이해 질문을 다음 세션이 읽도록 남긴다. 보조는 자기 보고서에서만 정리한다.
3. 커밋한다: `handoff: <한 줄 상태>`.
4. 새 세션을 사람이 연다. 첫 지시는 「메인」이면 된다. AGENTS.md와 역할 문서의 새 세션 순서로 읽고 현재 상태를 다섯 줄로 요약한 뒤 합의 범위에서 이어간다.
5. 요약이 틀리면 사람이 고쳐 준다. 메인은 그 차이를 `STATE.md` 에 고친다. 새 업무 결정이나 기록 충돌이 있으면 그 부분부터 확인한다.

## 보조 세션
새 보조 세션은 첫 지시를 「검증」 또는 「이해 도우미」로 시작한다. 같은 과제 폴더의 자기 역할 보고서에 결과를 남기면 메인이 다음 작업 경계에서 읽는다. 보조 교체 시에도 같은 역할 이름을 사용하고 기존 보고서를 읽는다.
