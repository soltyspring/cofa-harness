# 인계 — 세션을 끊고 이어 가기

대화가 길어지면 압축을 거듭하지 말고 인계한다. 시점을 미리 정한다.

## 언제
- 단계가 바뀔 때(합의 → 구현, 구현 → 마무리)
- 시작 후 약 90분
- 같은 오류를 두 번 고쳤는데 또 날 때

## 어떻게
1. `STATE.md` 의 「현재」를 덮어쓴다: 단계 · 된 것 · 남은 것(우선순위) · 알려진 문제 · 마지막 검사 · 다음 할 일. 「다음 할 일」은 새 세션이 바로 실행할 수 있게 파일과 명령까지 쓴다.
2. 요구가 바뀌었으면 `PLAN.md` 도 고친다.
3. 커밋한다: `handoff: <한 줄 상태>`.
4. 새 세션을 연다. 첫 지시: 「AGENTS.md 의 새 세션 순서대로 읽고, 현재 상태를 다섯 줄로 요약해라. 요약이 맞는지 내가 확인한 뒤 시작한다.」
5. 요약이 틀리면 고쳐 준다. 그 차이를 `STATE.md` 에 고친다.

## 보조 세션
진행 점검이나 교차 리뷰용으로 세션을 하나 더 열 때는 첫 지시를 「보조. 파일은 고치지 마라. `STATE.md` 와 `PLAN.md` 를 읽고 …」로 시작한다. 보조 세션의 제안은 사람이 메인 세션에 옮겨 적용한다.
